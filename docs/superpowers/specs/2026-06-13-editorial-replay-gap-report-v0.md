# Editorial Replay Gap Report v0

Date: 2026-06-13
Status: completed
Scope: bounded `call_of_duty` proof-path diagnosis only

## Objective

Determine why canonical fused-review and runtime-review decisions are not replayable from preserved repo artifacts alone. Identify:

- which review artifacts are external-only
- which state transitions are sidecar-bound
- which missing contracts prevent deterministic editorial-state regeneration

Non-goals:

- implementing a fix
- widening beyond the current `call_of_duty` proof path
- changing review policy
- changing lifecycle policy

## Executive Result

Editorial replay is currently **not deterministic from repo state alone**.

The main causes are:

1. review source artifacts live partly outside the repo
2. review application is written onto specific sidecar files, not onto a replayable decision ledger
3. fused candidate identity is derived from `fused_sidecar_path`, so fresh reruns create new candidate identities even when the underlying gameplay event is the same

## Findings

### 1. Review source artifacts are external-only

Both review session manifests point to decision-source artifacts under `GPT-Codex-Repo`, not just repo-local files.

Runtime review examples:

- `gpt_repo = /Users/tj/GPT-Codex-Repo`
- `gpt_processed_path = /Users/tj/GPT-Codex-Repo/processing/...`
- `gpt_meta_path = /Users/tj/GPT-Codex-Repo/inbox/...`

Fused review examples:

- `gpt_repo = /Users/tj/GPT-Codex-Repo`
- `gpt_processed_path = /Users/tj/GPT-Codex-Repo/processing/...`
- `gpt_meta_path = /Users/tj/GPT-Codex-Repo/inbox/...`

Implication:

- the repo preserves session manifests and applied sidecar mutations
- it does **not** preserve a fully self-contained in-repo decision source for replay
- `apply_*_review` depends on `gpt_meta_path` files when reconstructing decision state

### 2. Review decisions are applied onto specific sidecar files

`apply_runtime_review` writes a `runtime_review` block directly into the runtime sidecar referenced by the session item.

`apply_fused_review` writes `fused_review.events[event_id]` directly into the fused sidecar referenced by the session item.

Observed result:

- canonical reviewed runtime sidecar contains `runtime_review`
- canonical reviewed fused sidecar contains `fused_review`
- fresh rerun sidecars contain neither

Implication:

- review state is not regenerated by recomputing the clip
- review state only exists where it was previously written
- rerunning analysis creates a mechanically equivalent sidecar, but not an editorially equivalent sidecar

### 3. Fused candidate identity is sidecar-bound

Candidate identity is derived from:

- `game`
- `source`
- `fused_sidecar_path`
- `event_id`

That means the same fused event on a different fused sidecar path produces a different `candidate_id`.

Observed consequence:

- canonical fused sidecar candidate ids differ from fresh rerun candidate ids
- fresh rerun lifecycle rows enter the registry as new `pending_review` candidates
- canonical approved or rejected decisions do not attach to those new candidate ids

Implication:

- editorial replay is blocked even when event content is stable
- the current identity contract treats sidecar materialization path as part of candidate identity

### 4. Lifecycle state is derived, not durably re-applied

Derived lifecycle logic currently resolves roughly as:

- `selection_manifest + approved review -> selected_for_export`
- `export_row + selection_manifest + approved review -> exported`

Implication:

- the registry can infer lifecycle from preserved artifacts
- but it cannot deterministically reconstruct editorial state for fresh reruns unless those fresh reruns also carry the right review attachment and selection/export lineage

This is why fresh reruns stayed at `pending_review` while canonical reviewed artifacts had already advanced further.

### 5. The repo preserves outcome state better than decision provenance

What is preserved well:

- canonical reviewed sidecar payloads
- session manifests
- downstream selection and export artifacts

What is not preserved as a replayable contract:

- an in-repo, sidecar-independent review decision ledger
- a canonical mapping from prior reviewed event identity to freshly rerun event identity
- a deterministic reapply step that can say:
  - this fresh fused event is the same editorial object as that previously reviewed fused event

## Replay Failure Surface

Current replay works at:

- runtime analysis generation
- fused analysis generation
- highlight selection export

Current replay breaks at:

- runtime review regeneration
- fused review regeneration
- downstream lifecycle regeneration that depends on reviewed state attaching to fresh artifacts

## Missing Contracts

The current proof path is missing three contracts needed for deterministic editorial replay.

### Missing Contract A: in-repo review decision artifact

Needed property:

- review decisions must be preserved in a repo-local artifact that is sufficient for reapply without reading external `GPT-Codex-Repo` metadata

Current gap:

- session manifests reference external review-source files
- sidecars preserve applied status, but not a separate canonical decision record for replay

### Missing Contract B: stable editorial identity

Needed property:

- the same underlying fused event must keep the same editorial identity across reruns

Current gap:

- candidate identity includes `fused_sidecar_path`
- fresh sidecar path means fresh candidate id

### Missing Contract C: deterministic review reapply bridge

Needed property:

- given:
  - fresh runtime or fused sidecar
  - stable reviewed identity
  - preserved decision record
- the system should be able to reapply editorial state without manual or external bridge work

Current gap:

- review bridges are built for prepare/apply against GPT-Codex review files
- they are not built for deterministic repo-local rehydration of already-made decisions

## Classification

Current proof-path editorial state is:

- mechanically inspectable
- historically preserved
- partially externalized
- not deterministically replayable

Short classification:

- `Editorial Replay = Incomplete`

## Narrowest Conclusion

The highlight proof path does not currently fail because the review outcome is missing.

It fails because the review outcome is preserved as:

- sidecar-local mutation
- session-manifest references to external GPT artifacts
- downstream derived lifecycle state

instead of as:

- stable, sidecar-independent editorial identity
- repo-local decision provenance
- deterministic reapply contract

## Recommended Next Step

Do not widen scope.

The next useful step is to define the minimum artifact contract needed for bounded editorial replay in the existing `call_of_duty` proof path, before designing any fix.
